# OpenClaw 长任务异步执行方案

> 解决 AI Agent 执行长任务时的阻塞问题

---

## 问题背景

OpenClaw 默认采用单会话串行执行模型，长任务会阻塞主 Agent，导致用户无法执行其他操作或查询进度。

**典型场景：**
- 数据迁移（10000+ 条记录）
- 批量文件处理（20+ 文件）
- 复杂分析任务（持续数分钟）

---

## 核心解决方案

### 1. 简化方案：MEMORY.md 规则驱动

**核心思路：** 不需要复杂代码，通过 MEMORY.md 配置规则，由主 Agent 直接判断并派生子 Agent。

**长任务判断标准（写入 MEMORY.md）：**

| 类型 | 示例 |
|------|------|
| **长任务**（派生子 Agent） | 文件处理（>20个文件）、代码执行、批量操作、数据迁移、网络请求、长时间计算 |
| **短任务**（直接回复） | 问答咨询、代码审查、文本分析、简单查询 |

**执行流程：**
```
用户请求 → 主Agent查MEMORY.md判断 → 长任务? → 派生子Agent + 回复"已受理"
                    ↓ 否
              直接执行并回复
```

**优点：**
- 无需标记检测代码
- 无需修改 OpenClaw 流程
- 规则可动态调整
- 实现最简单

### 2. 异步执行架构（完整版）

```
用户请求 → 检测[LONG_TASK] → 派生子Agent → 立即返回"已受理"
                              ↓
                       子Agent后台执行
                       定时同步进度 → HEARTBEAT.md
```

### 2. 关键机制

| 机制 | 作用 |
|------|------|
| `[LONG_TASK]` 标记 | 自动识别长任务，触发异步执行 |
| 子 Agent 隔离 | 使用 `sessions_spawn` 启动独立会话 |
| HEARTBEAT.md 同步 | 文件级进度持久化 |
| 停止信号 | 文件级任务取消机制 |
| 超时检测 | 自动标记僵死任务 |

## 技术亮点

1. **非阻塞执行** - 长任务不占用主 Agent 会话
2. **进度可查询** - 用户可随时查看任务进度
3. **可控可取消** - 支持用户主动取消任务
4. **高可靠性** - 超时检测、故障恢复、持久化记录
5. **重启恢复** - 可从 HEARTBEAT.md 恢复任务状态
